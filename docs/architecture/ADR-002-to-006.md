# Architecture Decision Records (ADR-002 … ADR-006)

Companion to `ADR-001`. Each records a decision, alternatives, and rationale.

---

## ADR-002 — Single company-config source of truth

- **Status:** Accepted · **Date:** 2026-10-11
- **Decision:** All company facts live in `src/config/company.js`. Pages are rendered from it by
  `tools/build.mjs`, so phone/email/WhatsApp/location/tagline cannot drift across pages.
- **Alternatives:** (a) hard-code per page — rejected (drift, the exact ISS-002 bug); (b) fetch from
  an API — rejected (needs a backend, out of scope).
- **Consequences:** one place to edit contact info; tests assert every rendered page matches config.
- **Rollback:** original root `*.html` remain valid without the build.

## ADR-003 — CSS custom properties as the design-token system

- **Status:** Accepted · **Date:** 2026-10-11
- **Decision:** Formalize the existing CSS custom properties (`--ink`, `--gold`, `--paper`,
  spacing, radii, shadows, motion tokens) as the documented token system in
  `docs/design/DESIGN_SYSTEM.md`. No CSS framework.
- **Alternatives:** Tailwind — rejected (build + utility churn for a static site; ADR-001);
  CSS-in-JS — rejected (needs a JS runtime/framework).
- **Consequences:** zero-build theming; tokens are readable and enforceable by review.

## ADR-004 — Dependency-free motion (CSS + tiny vanilla JS)

- **Status:** Accepted · **Date:** 2026-10-11
- **Decision:** Implement subtle motion with CSS transitions/keyframes plus a ~40-line vanilla
  `IntersectionObserver` reveal in `src/js/motion.js`. Honour `prefers-reduced-motion`.
- **Alternatives:** Motion/Framer Motion, GSAP, Lenis — rejected here: they are either React-bound
  (Motion React) or add weight for effects we can achieve with a few lines of CSS; the brief warns
  against "multiple overlapping animation engines and unnecessary dependencies".
- **Consequences:** tiny, fast, accessible; no perpetual/parallax/3D motion (per design rules).
- **Future:** if richer scroll-linked motion is ever required, Motion's **vanilla JS** build (MIT)
  is the first candidate and would be evaluated in a new ADR.

## ADR-005 — Testing with Node built-ins, no dependencies

- **Status:** Accepted · **Date:** 2026-10-11
- **Decision:** `tests/run.js` uses only Node core modules (`node:fs`, `node:path`, `node:url`,
  `assert`). Runnable via `node tests/run.js` with no install.
- **Alternatives:** Jest/Vitest (install + config), Playwright (browser download; not available in
  this environment) — rejected for this phase. Playwright visual/E2E is listed as a future task.
- **Consequences:** tests run anywhere Node exists; prove links, consistency, encoding, assets,
  JSON-LD, SEO/a11y. Automated results are separated from manual checks.

## ADR-006 — Inline SVG for key icons; unicode only for decoration

- **Status:** Accepted · **Date:** 2026-10-11
- **Decision:** Use inline SVG for meaningful icons (WhatsApp). Use unicode glyphs only where purely
  decorative and `aria-hidden`. Do not add an icon library/font as a dependency.
- **Alternatives:** Lucide npm package (ISC, tree-shakable) — deferred; only a handful of icons are
  needed, so inlining avoids a dependency. If the icon set grows, Lucide (vanilla build) is the
  recommended addition.
- **Consequences:** consistent rendering for critical icons; zero deps.
